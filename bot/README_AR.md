# 🤖 بوت ديسكورد — مترجم المانجا العربي

أوامر البوت (كلها تعمل عبر طابور في PostgreSQL ويشغّل `manga.py` كعملية منفصلة):

| الأمر | الوظيفة | الناتج |
|---|---|---|
| `/clean` | مسح النص من الفقاعات | ZIP صفحات نظيفة |
| `/extract` | استخراج النصوص الأصلية | `extract.txt` + `extract.json` |
| `/typer` | تنظيف + إحداثيات الفقاعات | `typer.zip` (للاستيراد في TypeR Web) |
| `/chapter` | صور نظيفة + `chapter.json` (صيغة manhuarmtl-v1) | `chapter.zip` = مجلد `images/` + `chapter.json`؛ `translate:True` يترجم النصوص للعربية (اختياري)؛ `provider` = Ollama المحلي أو API (gemini/openai/deepseek/groq/openrouter/xai/together) بشرط وجود المفتاح في `.env` |
| `/translate` | ترجمة عربية كاملة عبر Ollama | ZIP أو PDF |
| `/status` `/history` `/cancel` `/queue` `/ping` | متابعة وإدارة | — |

بعد كل مهمة يعرض البوت: عدد الصفحات (والفارغة منها)، الفقاعات، توزيعها (حوار / مؤثرات / إعلانات)،
النبرات، الحوارات المترجمة، طريقة المسح، المدة وحجم الناتج. تُحذف الملفات من السيرفر بعد 20 دقيقة.

## التشغيل
```bash
pip install -r requirements.txt -r bot/requirements.txt
cp bot/.env.example bot/.env      # عبّئ DISCORD_TOKEN و DATABASE_URL
createdb mangabot                 # PostgreSQL (الجداول تُنشأ تلقائياً)
python -m bot
```
ادعُ البوت بـ scopes: `bot` و`applications.commands` (لا يحتاج أي privileged intents).
للترجمة شغّل Ollama (`ollama pull qwen2.5:7b-instruct`)، أو وجّه `OLLAMA_URL` لجهاز آخر.

## أوامر قديمة ظاهرة / مكررة؟
`tree.sync()` يستبدل الأوامر **العامة** لنفس التطبيق تلقائياً. اللي يبقى هي أوامر **السيرفر** اللي سجّلها بوت قديم:
- شغّل مرة واحدة: `python -m bot.purge_commands` (يمسح العام + أوامر كل السيرفرات) ثم شغّل البوت.
- أو ضع `PURGE_OLD_COMMANDS=1` ليمسح أوامر السيرفرات عند كل تشغيل.
- لو الأوامر القديمة من **تطبيق/توكن مختلف** فلا يمكن مسحها بهذا التوكن: اطرد البوت القديم من السيرفر أو استخدم توكنه.
- قد يتأخر اختفاؤها من واجهة ديسكورد قليلاً؛ أعد تشغيل التطبيق (Ctrl+R).

## "الملف أكبر من الحد المسموح"
الحد الافتراضي `MAX_UPLOAD_MB=100`. ديسكورد نفسه يحدّ المرفقات (10MB بدون Nitro)، فارفع `MAX_UPLOAD_MB` لو عندك Nitro، أو قسّم الفصل. الصفحات القصوى منفصلة (`MAX_PAGES`).

## متابعة المهمة (شغّال أم عالق؟)
رسالة الحالة تتحدّث كل ≤30 ثانية (`HEARTBEAT_SECONDS`) حتى لو `manga.py` صامت، وتعرض:
شريط التقدم، الصفحات `7/30`، الفقاعات، الوقت المنقضي، الوقت المتبقي تقريباً، المرحلة الحالية،
و**آخر نشاط** (يتحدّث لحظياً عند ديسكورد). مؤشر الصحة: 🟢 يعمل · 🟡 خطوة طويلة (>2 دقيقة بلا مخرجات،
طبيعي للترجمة على CPU) · 🔴 قد يكون عالقاً (>10 دقائق). نفس المعلومات في `/status`.

## ملف واحد أكبر من حد الرفع (مثل `strip_001.png`)
`manga.py` يدمج صفحات الويبتون في **أشرطة طويلة** (حتى 8000px). شريط PNG واحد قد يتجاوز حد الرفع (10MB بدون Boost).
البوت الآن: يحوّله إلى JPEG بأعلى جودة تناسب الحد، وإن لم يكفِ يقصّه إلى شرائح عند صفوف فارغة (لا يقطع نصاً)،
ويذكر ذلك في الملاحظات. أرقام: ملفات الرسالة الواحدة يُراعى فيها **مجموع** الحجم لا حجم كل ملف.
تتقطع بين صفحتين. لـ `/typer` لا يُقصّ ولا يُحوَّل (إحداثيات الفقاعات مرتبطة بأسماء وأبعاد الصور).

## `/typer`: الناتج كان 170MB؟
تصدير TypeR في `manga.py` كان يكتب كل صفحة PNG بلا ضغط (أشرطة 8000px ⇒ مئات الميغا). الآن:
- يحترم `MANGA_TYPER_FORMAT` (البوت يمرّر `format`، الافتراضي JPG) — نفس أبعاد الصور فالإحداثيات سليمة.
- لو تجاوز حد الرفع: تُضغط الصفحات الكبيرة في مكانها (نفس الاسم والأبعاد)، ثم يُقسَّم إلى
  `typer_part1.zip`, `typer_part2.zip`… وكل جزء **مهمة TypeR مستقلة** (لها `typer_job.json` خاص) تُستورد وحدها.
- نفس الصيغة المضغوطة تُستخدم لمجلد التصدير في `/clean` و`/translate` (توفير قرص ووقت).

## رفع النتائج الكبيرة على gofile
لو النتيجة أكبر من حد ديسكورد (مثلاً تصدير TypeR 170MB) ضع `EXTERNAL_HOST=gofile`: البوت يرفع الملف **بالجودة الأصلية** ويرسل الرابط في الرسالة. لو فشل الرفع يرجع تلقائياً للضغط/التقسيم عبر ديسكورد مع ملاحظة.
- `GOFILE_TOKEN` اختياري (يربط الملفات بحسابك). أي شخص معه الرابط يقدر يحمّل.
- **لم يُختبر مع gofile الحقيقي** (اختُبر على سيرفر تجريبي فقط). جرّبه مرة: `python -m bot.hosting ملف.zip` — لو طلع `OK ... https://gofile.io/d/...` يبقى شغال.

## استقبال الفصل برابط بدل الرفع
كل أوامر `/clean` `/extract` `/typer` `/translate` فيها خيار `link`: الصق رابط **Google Drive** (ملف مشارك «أي شخص لديه الرابط») أو **Gofile** بدل ما ترفع الملف (حد الحجم `MAX_LINK_MB=500`، وتقدر توقفه بـ `ALLOW_LINKS=0`).
- لازم ملف واحد (ZIP أو PDF أو صورة).
- **مجلد Drive** مدعوم بإحدى طريقتين: (١) **Colab**: `GOOGLE_DRIVE_ACCESS = True` في الـ notebook ← نافذة «Sign in with Google» مرة واحدة، فيقرأ البوت ملفات/مجلدات Drive **بحسابك** (حتى الخاصة) بدون مفتاح؛ الخطوة اختيارية (`False` = تخطّي، أو اضغط إلغاء). (٢) خارج Colab: `GOOGLE_API_KEY` للمجلدات المشاركة للعامة (أو `GOOGLE_TOKEN_FILE` لو عندك توكن). الشرح التالي ينطبق على الطريقتين (مفتاح مجاني من Google Cloud Console مع تفعيل Drive API): البوت يحمّل الصور ويضغطها ZIP بترتيب الأسماء الطبيعي (1,2,10). بدون المفتاح اضغط الفصل ZIP.
- البوت يتصل بمواقع Drive/Gofile فقط، ويتأكد من نوع الملف من محتواه، ويوقف التحميل لو تعدى الحد.
- **لم يُجرَّب مع Drive/Gofile الحقيقيين** (اختُبر على سيرفرات تجريبية). جرّب مرة: `python -m bot.fetch "الرابط"`.

## المحرك الجديد (فرع `new-engine`)
- **التنظيف / الاستخراج / TypeR** يعملون الآن على محرك فورك `amirwolf512k` (`manga.py` + `manga_sections/`): تنظيف أدق، OCR أسرع، حماية أفضل لحواف الفقاعات.
- **الصفحات تُعالج كما هي**: لا دمج في شرائط طويلة ولا «إصلاح حواف» يلصق الصفحات ببعضها (`--stitch-max-height 0 --no-seam-repair` دائماً)، فاختفت أخطاء «سلسلة الصور/موضع قص آمن». عدد صفحات الناتج = عدد صفحات الإدخال (الصفحات الفارغة تبقى كما هي).
- **`--export-typer DIR`** أُضيف للمحرك الجديد (مع `--clean-only`): يكتب صفحات نظيفة + `typer_job.json` (+ `DIR.zip`).
- **الترجمة العربية (Ollama)** ما زالت على المحرك العربي السابق `legacy/manga_ar.py` (المحرك الجديد يترجم للفارسية فقط؛ نقل العربية له يحتاج إعادة كتابة البرومبتات). غيّر المسار بـ `LEGACY_SCRIPT`.
- المحرك الجديد **لا يحدّث نفسه من GitHub** (عُطّل `_UPDATE_MIRRORS`) حتى لا تُمحى تعديلاتنا.
- اختُبر هنا فعلياً بصفحات اصطناعية (clean / extract / typer كلها نجحت بالموديلات الحقيقية على CPU). لم يُختبر على فصل مانجا حقيقي ولا على GPU.
